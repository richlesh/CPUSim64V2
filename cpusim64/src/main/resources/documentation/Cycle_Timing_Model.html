CPUSim64 Cycle Timing Model

Instructions on a modern RISC processor each take multiple cycles to pass through the CPU's execution stages (this is the instruction's latency). However, because these stages are pipelined—allowing several instructions to be processed simultaneously at different stages—the processor can often complete roughly one instruction per cycle in terms of throughput.

Some instructions break this ideal. Operations such as division are typically not fully pipelined and take many cycles, while events like interrupts incur additional overhead from flushing the pipeline and saving processor state. This table documents the effective number of cycles attributed to each instruction.

Notes

  • Each cycle count = a base 1-cycle instruction fetch, plus 1 cycle for every memory word read or written, plus a per-instruction extra-cycle value defined in the instructions.data resource. The simulator loads that table at startup, so timings can be retuned by editing it without changing code.
  • Floating point: ADD, SUBTRACT, MULTIPLY, and DIVIDE use the floating-point cycle value (fadd, fsubtract, fmultiply, fdivide) whenever at least one operand is a floating-point value; otherwise the integer value is used. RECIP is timed as an FP divide.
  • SAVE/RESTORE: N = number of registers in the range (e.g., SAVE R0, R28 → N = 29). The per-register cost comes from the N stack writes/reads (1 cycle each); the instruction itself adds no extra beyond fetch.
  • CAS: A compare-and-swap on heap or stack memory uses an atomic primitive with a 2-cycle extra cost (3 total). A CAS on shared memory additionally performs a separate read and write (2 memory cycles), for 5 total.
  • Conditional branches: JUMP, CALL, and INTERRUPT charge the xxx0 value when the condition is not taken and the xxx1 value when taken; unconditional forms use the base key.
  • INTERRUPT: The 10-cycle extra (11 total) represents the trap/return cost. Actual handler execution time is tracked separately as wall-clock “System Time.”
  • IN/OUT: Each port access is charged a fixed 1 cycle for the instruction itself. The real time spent performing the underlying port transfer (e.g. file or device I/O) is measured separately and added to wall-clock “System Time,” the same way interrupt-handler time is tracked, so slow I/O does not distort the deterministic cycle count.
